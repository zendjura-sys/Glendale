# Edge-вузол: LiveKit + CDN (Oracle Cloud та ін.)

Окрема машина знімає з основного сервера голос (LiveKit + TURN) і віддачу файлів
(`/build`, `/storage`, `/images`) через кеш на своєму диску. Домен не потрібен:
скрипт бере ім'я `<ip-через-дефіси>.sslip.io` і отримує на нього сертифікат Let's Encrypt.

- Скрипт: `deploy/edge/setup-edge.sh` (ключі LiveKit — лише на вузлі й у налаштуваннях сайту, не в репозиторії).
- nginx: `deploy/nginx/edge.conf` — `/rtc`, `/twirp` → LiveKit; файли → кеш (шматки по 4 МБ, CORS).
- Перемикач: **Адмін-панель → Інтеграції → «Edge-вузол: сервер голосу й файлів»** — адреса вузла,
  «Сервер голосу» й «Сервер файлів»: «Основний» або «Edge-вузол». `.env` міняти не треба.
  Логіка — `App\Services\Edge\EdgeNode` (LiveKit бере адресу звідти, CDN підставляється в `asset()` і диск `public`).
- Безпека: щохвилини (`edge:probe` у `routes/console.php`) сайт перевіряє `/edge-health`;
  два збої поспіль — голос і файли автоматично йдуть з основного сервера, доки вузол не оживе.
- Запасний спосіб без адмінки: `ASSET_URL`, `MEDIA_URL`, `LIVEKIT_URL` у `.env`.
- Перевірка: `https://<вузол>/edge-health`, заголовок `X-Edge-Cache: HIT|MISS` на файлах.

Порти (Oracle → VCN → Security List, Ingress, 0.0.0.0/0): TCP 80, 443, 7881, 5349; UDP 3478, 50000–60000.
Скрипт сам відкриває їх у iptables вузла (в образах Oracle вони закриті за замовчуванням).
